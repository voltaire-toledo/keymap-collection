# VT-ZMK-B1-Pro Design Document

## ZMK Shield Architecture
The ZMK shield for the Keychron B1 Pro is composed of several interlocking files that define both the hardware and software configuration:

* **`Kconfig.shield`**: A Zephyr build system declaration. It alerts the compiler that the `keychron_b1_us` shield exists during the build process.
* **`.conf` (`keychron_b1_us.conf`)**: The primary ZMK settings file. Used to toggle global firmware features like Deep Sleep, Bluetooth TX power, battery reporting, and RGB underglow.
* **`.overlay` (`keychron_b1_us.overlay`)**: The hardware Devicetree map. This file tells the microcontroller exactly which physical GPIO pins are wired to the rows and columns of the switch matrix. 
* **`.keymap` (`keychron_b1_us.keymap`)**: The logical layout mapping. Sits on top of the `.overlay` to assign logical keycodes, macros, and layers to the physical switch matrix.

## The Build System (West, CMake, and Ninja)
Unlike traditional C projects that use a single `Makefile`, ZMK relies on Zephyr's highly modular, three-tier build architecture:

1. **West (The Meta-Tool)**: The primary command-line tool (`west build`). It manages all dependencies across multiple repositories and acts as the orchestrator for the build process.
2. **CMake (The Generator)**: West invokes CMake, which scans the root `CMakeLists.txt` (inside the `app/` folder), aggregates all of the `.conf` and `.overlay` files, and generates a massive, hardware-specific configuration.
3. **Ninja (The Compiler Driver)**: Ninja is a modern, drastically faster alternative to `make`. It takes the blueprints generated by CMake and parallelizes the C/C++ cross-compilation using the Zephyr SDK, ultimately spitting out the finalized `.uf2` firmware image.

## References and Validations
* **Homerow Mods Validation**: [Keychron/qmk_firmware Issue #455](https://github.com/Keychron/qmk_firmware/issues/455) (Authored by `4cio`). 
  * Validates that the Keychron B1 Pro stock firmware uses `hold-preferred` mod-tap, causing phantom modifiers.
  * Confirms that injecting custom firmware with `flavor = "tap-preferred"` and `quick-tap-ms = <200>` entirely eliminates the phantom modifier issue during fast typing on the B1 Pro.

## Keymap Strategy & Ergonomics Rules

1. **Shortcut Sequence Efficiency**:
   * *Shortcut key sequences should not exceed the number of steps without a shortcut.*
   * Multi-tap dances must not exceed 2 taps (e.g. 1-tap open bracket, 2-tap close bracket).
   * 3-step or compound actions (e.g. `open + close + left arrow`) are mapped to dedicated momentary macro layers accessed via bilateral hold keys (`Z` and `/`), rather than triple-tap sequences.
